# PARADOX LAB V0.8 — model defect hunting

## Capabilities
- Per-model fingerprints by task family and error category.
- Repeated-item stability detection; stable means the same validated error appears at least the configured number of trials.
- Cross-model transfer matrix based on shared challenge IDs and stable failures.
- Provider-neutral sequential adapter runner.
- Model-in-the-loop minimization using a caller-provided adapter.

## Adapter contract
An async function receives (prompt, context) and returns a JSON string or parsed response accepted by V0.6. The context includes modelId, challenge and trial. Keep credentials in a trusted server process, never in browser JavaScript.

## Interpretation safeguards
- A stable failure is an operational repeatability label, not proof of a general capability defect.
- Transfer rate is descriptive and depends on the tested challenge set; report denominators.
- Compare models with fixed prompt, decoding parameters, retry policy and token budget.
- Exclude ADAPTER_ERROR from model accuracy denominators; report provider failures separately.
- Minimization is 1-minimal under available transformations, not globally minimum. Re-test minimized case and parent on fresh runs.
- No live provider was called by the included mock tests.
